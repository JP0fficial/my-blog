# Plan 서브에이전트 지침 — 픽셀 아트 에디터

## 할 일
`apps/pixel-editor/` 웹앱의 구현 계획을 세워 `apps/pixel-editor/spec.md` **한 파일만** 작성한다.
코드는 쓰지 않는다. 다른 파일은 만들거나 고치지 않는다.

## 사용자 요청
16×16 격자에 도트를 찍어 그림을 그리는 픽셀 아트 에디터. 완성하면 PNG로 저장. 색상 팔레트 포함.

## 계획에 포함할 내용
1. 기능 범위: 꼭 필요한 것(펜, 지우개, 팔레트 색 선택, 전체 지우기, PNG 저장)과 넣으면 좋은 것(채우기, 스포이트, 실행 취소/다시 실행, 사용자 지정 색 `<input type="color">`, 격자선 표시 토글)을 나누고, 이번에 넣을 것을 정한다. 과하게 키우지 않는다.
2. 팔레트: 기본 색 16개 내외 구성(투명 포함 여부), 선택 색 표시
3. 그리기 방식: `<canvas>` 한 장 vs DOM 격자 중 선택과 이유. 마우스 드래그·터치 드래그로 연속 그리기(Pointer Events), 드래그 중 페이지 스크롤 방지, 같은 칸 중복 처리
4. PNG 저장: 배경 투명 여부, 저장 배율(예: 1×=16px는 너무 작으니 기본 배율과 선택지), 확대 시 흐려지지 않게(`imageSmoothingEnabled = false` 또는 픽셀 직접 채우기), 파일 이름, 다운로드 방식(`canvas.toBlob` + `<a download>`)
5. 저장: 작업 중인 그림을 `localStorage`에 자동 저장할지 (키 이름은 `pixel-editor:` 접두사)
6. 화면 구성: 모바일 우선 레이아웃 (360px에서 캔버스·팔레트·도구가 어떻게 배치되는지), 데스크톱 확장
7. 테마: 블로그와 같은 `localStorage` 키 `theme`로 라이트/다크를 따른다. `apps/tile-merge/index.html`과 `main.js`의 테마 처리 방식을 참고해 같은 방식으로 맞춘다. 투명 칸은 체크무늬로 표시
8. 접근성: 도구·팔레트 버튼에 `aria-label`과 `aria-pressed`, 키보드 단축키(있다면), 색 이름 제공, 터치 대상 44×44px
9. 파일 구조: `apps/pixel-editor/` 안에 `index.html`, `style.css`, 로직 모듈(DOM 없는 순수 함수: 격자 데이터, 채우기, 실행 취소 기록 등), 화면·입력 모듈, `preview.svg`(블로그 카드용). 외부 라이브러리 없이
10. Review 체크리스트: 로직 테스트 케이스(예: 채우기 경계, 실행 취소 순서), PNG 실제 크기·픽셀 색 확인 방법, 360px 모바일, 라이트/다크

## 참고할 파일 (읽기만)
