# Plan 서브에이전트 지침 — 타일 합치기 퍼즐

## 할 일
`apps/tile-merge/` 웹앱의 구현 계획을 세워 `apps/tile-merge/spec.md` **한 파일만** 작성한다.
코드는 쓰지 않는다. 다른 파일은 만들거나 고치지 않는다.

## 사용자 요청
방향키로 숫자 타일을 밀어서 같은 숫자끼리 합치는 슬라이딩 퍼즐 게임. 점수판 포함.

## 독창성 조건 (중요)
특정 기존 게임을 그대로 재현하지 않는다. 장르의 기본 메커니즘(격자 위 타일을 한 방향으로 밀기, 같은 값 합치기, 이동마다 새 타일 생성)은 쓰되:
- 기존 게임의 이름·로고·제목(예: 숫자 "2048"을 제목이나 목표로 내세우는 것)을 쓰지 않는다. 앱 이름은 "타일 합치기"(영문 Tile Merge)로 한다.
- 기존 게임 특유의 베이지/주황 계열 배색과 레이아웃을 따라 하지 않는다. 블로그 테마(`css/style.css`의 CSS 변수, 라이트/다크)와 어울리는 독자적인 배색을 제안한다.
- 특정 숫자 도달을 "승리"로 두지 않고, 더 이상 움직일 수 없을 때까지 하는 무한 모드 + 최고 점수 기록으로 설계한다.

## 계획에 포함할 내용
1. 게임 규칙 (격자 크기, 새 타일 값과 확률, 합치기 규칙 — 한 번 이동에 한 타일은 한 번만 합쳐짐, 점수 계산, 게임 오버 조건)
2. 화면 구성 (제목, 현재 점수, 최고 점수, 새 게임 버튼, 게임판, 게임 오버 안내)
3. 조작: 방향키 + WASD, 모바일 스와이프(터치), 스와이프 중 페이지 스크롤 방지
4. 저장: 최고 점수 `localStorage`, 진행 중인 판 저장 여부
5. 테마: 블로그와 같은 `localStorage` 키 `theme`로 라이트/다크를 따름 (`index.html` 상단 스크립트 참고). 독립 페이지이므로 자체 CSS에 변수를 정의
6. 애니메이션 범위 (타일 이동·생성·합치기, `prefers-reduced-motion` 대응)
7. 접근성 (점수 변화 `aria-live`, 버튼 라벨, 색만으로 값을 구분하지 않도록 숫자 표시)
8. 파일 구조: `apps/tile-merge/` 안에 `index.html`, `style.css`, `game.js`(규칙 로직, DOM 없음), `main.js`(화면·입력) 등. 외부 라이브러리 없이
9. 블로그 메인 카드용 미리보기 방법 (iframe 또는 정적 이미지 중 추천)
10. Review 단계에서 확인할 체크리스트 (규칙 테스트 케이스 예: `[2,2,2,2]` 왼쪽 → `[4,4,_,_]`, `[2,2,4,0]` → `[4,4,_,_]`, 360px 모바일)

## 참고할 파일 (읽기만)
- `index.html`, `css/style.css`, `js/theme.js`
- 블로그는 `node serve.mjs` 로 `http://localhost:8000`에서 열림

spec.md는 한국어로, 사용자가 읽고 승인할 수 있게 간결하게 쓴다. 끝나면 spec.md 핵심을 5줄 이내로 요약해 보고한다.
