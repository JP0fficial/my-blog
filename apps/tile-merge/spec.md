# 타일 합치기 (Tile Merge) — 구현 계획

방향키나 스와이프로 격자 위 숫자 타일을 한쪽으로 밀어 같은 숫자끼리 합치는 슬라이딩 퍼즐.
목표 숫자나 "승리"는 없고, 더 움직일 수 없을 때까지 점수를 쌓는 **무한 모드**이며 최고 점수를 기록한다.
외부 라이브러리·빌드 도구 없이 순수 HTML/CSS/JS(ES 모듈)로 만든다.

---

## 1. 게임 규칙

| 항목 | 내용 |
|---|---|
| 격자 | 4×4 (`game.js`에서 `size` 인자로 받되 화면은 4 고정) |
| 시작 | 빈 칸 중 무작위 2곳에 새 타일 |
| 새 타일 | 값 2 (확률 90%), 값 4 (확률 10%). 유효한 이동 뒤에만 1개 생성 |
| 이동 | 한 방향(상·하·좌·우)으로 모든 타일을 빈칸 없이 끝까지 민다 |
| 합치기 | 이동 방향 쪽 끝부터 검사해, 인접한 같은 값 두 타일을 합쳐 값을 2배로 |
| 합치기 제한 | 한 번 이동에서 **각 타일은 최대 한 번만** 합쳐진다 (합쳐 생긴 타일은 그 턴에 다시 합쳐지지 않음) |
| 유효한 이동 | 격자에 변화가 하나라도 있어야 유효. 변화 없으면 새 타일도 생기지 않고 턴도 넘어가지 않음 |
| 점수 | 합쳐서 생긴 타일 값의 합을 더한다 (예: 2+2 → 4점, 한 턴에 4와 8이 생기면 12점) |
| 게임 오버 | 빈칸이 없고, 상하좌우로 인접한 같은 값도 없을 때 |

**한 줄 처리 알고리즘 (왼쪽 기준)**: 0을 제거해 압축 → 앞에서부터 i, i+1이 같으면 합치고 i+2로 건너뜀 → 뒤를 0으로 채움.
다른 방향은 행/열을 뒤집거나 전치해 같은 함수를 재사용한다.

## 2. 화면 구성

위에서 아래로, 한 열 레이아웃(최대 폭 약 28rem, 가운데 정렬).

1. **헤더**: 블로그로 돌아가는 링크(`../../index.html`, "← 블로그"), 앱 제목 "타일 합치기", 테마 토글 버튼
2. **점수판**: "점수"와 "최고 점수" 두 상자를 나란히. 점수가 오르면 `+12` 같은 작은 숫자가 떠올랐다 사라짐
3. **새 게임 버튼**
4. **게임판**: 정사각형(`aspect-ratio: 1`), 폭은 화면에 맞춰 줄어듦. 빈 칸 16개 배경 + 그 위에 타일 레이어
5. **게임 오버 안내**: 게임판 위 반투명 오버레이 — "더 이상 움직일 수 없습니다", 최종 점수, (갱신 시) "최고 점수 갱신!", "다시 하기" 버튼
6. **조작 안내**(작은 글씨): "방향키 · WASD · 스와이프로 이동"

## 3. 조작

- **키보드**: `ArrowUp/Down/Left/Right`, `W/A/S/D`(대소문자 무관). 처리한 키만 `preventDefault()`로 페이지 스크롤을 막는다.
  입력란이나 버튼에 포커스가 있을 때 Space/Enter 등은 가로채지 않는다.
- **터치 스와이프**: 게임판에서 Pointer Events(`pointerdown`/`pointerup`, `pointerType` 무관) 사용.
  이동 거리 30px 이상일 때 가로·세로 중 큰 쪽 방향으로 판정.
- **스크롤 방지**: 게임판에 `touch-action: none` + `overscroll-behavior: contain`. 페이지 나머지는 정상 스크롤.
- **연타 처리**: 애니메이션 중 입력은 즉시 반영(이전 애니메이션을 끝 상태로 건너뜀)해 조작감이 밀리지 않게 한다.

## 4. 저장 (`localStorage`)

| 키 | 내용 |
|---|---|
| `tile-merge:best` | 최고 점수(숫자) |
| `tile-merge:state` | 진행 중인 판 `{ grid, score, over }` JSON — 매 유효 이동 후 저장 |

- 페이지를 다시 열면 저장된 판을 이어서 한다. 값이 깨졌거나 형식이 다르면 무시하고 새 게임.
- "새 게임" 클릭 시 진행 중 판은 덮어씀(확인 대화상자 없음 — 단순하게).
- `localStorage` 접근은 `try/catch`로 감싸 사생활 보호 모드에서도 게임은 동작.

## 5. 테마

- 블로그와 같은 키 `theme`(`light`/`dark`) 사용. `index.html` `<head>` 맨 앞에 블로그와 동일한 인라인 스크립트를 넣어 FOUC 방지.
- 토글 동작은 `js/theme.js`와 같은 방식이지만, 앱을 독립 폴더로 유지하기 위해 `main.js`에 작은 테마 모듈을 따로 둔다(블로그에서 바꾼 테마가 앱에도, 앱에서 바꾼 테마가 블로그에도 반영됨).
- 색은 `apps/tile-merge/style.css`의 `:root` / `[data-theme="dark"]` 변수로만 정의. 블로그 기본 변수(`--bg`, `--text`, `--text-muted`, `--accent`, `--border`)를 같은 값으로 복사하고, 게임용 변수를 추가한다.

**배색 방향**: 블로그 강조색(파랑)에 맞춘 **차가운 계열 그러데이션** — 값이 커질수록 하늘색 → 파랑 → 남색 → 보라 → 청록으로 진해진다. 베이지·주황 계열은 쓰지 않는다.

## 6. 애니메이션

- **이동**: 타일마다 고유 `id`를 두고, 위치를 `transform: translate()`로 지정해 `transition: transform 120ms ease`로 미끄러지게 한다.
- **생성**: 새 타일은 `scale(0) → scale(1)` 150ms.
- **합치기**: 두 타일이 같은 칸으로 이동한 뒤 하나로 바뀌며 `scale(1.12 → 1)` 150ms 튐.
- **점수**: `+N` 표시가 위로 떠오르며 사라짐(600ms).
- **`prefers-reduced-motion: reduce`**: 모든 transition/animation을 끄고 즉시 결과 상태로 그린다. `+N` 표시도 생략(점수 숫자는 그대로 갱신).

이를 위해 `game.js`의 `move()`는 결과 격자와 함께 **타일별 이동 정보**(`from`, `to`, `mergedFrom`, `isNew`)를 돌려준다.

## 7. 접근성

- 점수 영역: 별도 시각적 숨김 요소에 `aria-live="polite"` — 유효 이동마다 "점수 120, 12점 획득" 형식으로 알림(합쳐짐 없으면 알리지 않음).
- 게임 오버: `role="alert"`로 "게임 종료. 최종 점수 N점" 알림, 오버레이가 뜨면 "다시 하기" 버튼으로 포커스 이동.
- 게임판: `tabindex="0"`, `aria-label="게임판, 방향키로 타일 이동"`. 격자 전체를 읽어 주는 `role="grid"`는 과하므로 쓰지 않는다.
- 버튼: "새 게임", "다시 하기"는 보이는 텍스트 그대로, 테마 토글은 `aria-label`("다크 모드로 전환"/"라이트 모드로 전환").
- 값은 **항상 숫자로 표시** — 색은 보조 수단일 뿐.
- 터치 대상 최소 44×44px, 포커스 링(`:focus-visible`)은 `--accent`로 뚜렷하게.

## 8. 파일 구조

```
apps/tile-merge/
├── index.html   # 마크업, <head> 테마 인라인 스크립트, <script type="module" src="main.js">
├── style.css    # 테마 변수 + 레이아웃 + 타일 색/애니메이션 (모바일 우선)
├── game.js      # 순수 규칙 로직 — DOM·localStorage 없음
├── main.js      # 화면 렌더, 입력(키보드/스와이프), 저장, 테마 토글, aria-live
└── spec.md      # 이 문서
```

**`game.js` 공개 함수 (모두 순수 함수, 난수는 인자로 주입 가능)**

- `createGame(size = 4, random = Math.random)` → `{ grid, score, over }`
- `slideLine(line)` → `{ line, gained }` — 한 줄 왼쪽 처리(테스트의 핵심 단위)
- `move(state, direction, random)` → `{ state, moved, gained, tiles }`
- `canMove(grid)` → boolean
- `addRandomTile(grid, random)` → 새 grid

`grid`는 `number[][]`(0 = 빈칸)로 저장·직렬화가 쉽게 한다. 화면용 타일 id는 `main.js`가 관리한다.

## 9. 블로그 메인 카드 미리보기

**추천: 정적 이미지** (`apps/tile-merge/preview.png` 또는 SVG, 카드 클릭 시 앱으로 이동)

- iframe은 목록 페이지에서 게임 전체(스크립트·키 입력·`localStorage`)가 함께 로드되고, 카드 안에서 방향키가 페이지 스크롤과 충돌할 수 있다.
- 정적 이미지는 가볍고 라이트/다크 모두 무난하다. 가능하면 손으로 쓴 작은 **SVG**(타일 몇 개 + 앱 색 변수와 같은 색)로 만들어 용량을 최소화.
- 블로그 쪽 카드 연결(`index.html`/`list.js` 수정)은 이 계획의 범위 밖이며, 별도 승인 후 진행한다.

## 10. Review 체크리스트

**규칙 (`slideLine` / `move` 단위 확인, 왼쪽 기준)**

| 입력 | 결과 | 점수 |
|---|---|---|
| `[2,2,2,2]` | `[4,4,0,0]` | 8 |
| `[2,2,4,0]` | `[4,4,0,0]` | 4 (새 4와 기존 4가 다시 합쳐지지 않음) |
| `[4,4,8,8]` | `[8,16,0,0]` | 24 |
| `[2,0,0,2]` | `[4,0,0,0]` | 4 |
| `[2,4,2,4]` | `[2,4,2,4]` | 0, `moved=false` |
| `[0,0,0,2]` | `[2,0,0,0]` | 0, `moved=true` |
| `[8,8,8,0]` | `[16,8,0,0]` | 16 |

- 오른쪽/위/아래도 같은 줄을 방향만 바꿔 동일 결과가 나오는지 (예: `[2,2,2,2]` 오른쪽 → `[0,0,4,4]`)
- 변화 없는 이동에서 새 타일이 생기지 않는지
- 새 타일 확률: 고정 난수 주입으로 2/4가 기대대로 나오는지
- 게임 오버: 꽉 찬 체커 패턴 → `canMove=false`, 인접 같은 값 1쌍만 있어도 `true`

**화면·환경**

- [ ] 360px 너비에서 가로 스크롤 없음, 게임판이 화면 폭에 맞음

- [ ] 새로고침 후 진행 중인 판·최고 점수 유지, 깨진 저장값에서도 새 게임으로 복구
- [ ] 블로그에서 바꾼 테마가 앱에 반영(반대도), 로드 시 깜빡임 없음
